#fpocket install in ubuntu
sudo apt-get install libnetcdf-dev
git clone https://github.com/Discngine/fpocket.git
cd fpocket
make 
sudo make install
#install miniconda into linux
https://www.anaconda.com/docs/getting-started/miniconda/install#linux-2
mkdir -p ~/miniconda3
wget https://repo.anaconda.com/miniconda/Miniconda3-latest-Linux-x86_64.sh -O ~/miniconda3/miniconda.sh
bash ~/miniconda3/miniconda.sh -b -u -p ~/miniconda3
rm ~/miniconda3/miniconda.sh
After installing, close and reopen your terminal application or refresh it by running the following command:
source ~/miniconda3/bin/activate
Then, initialize conda on all available shells by running the following command:
conda init --all
#install parallel
sudo apt install parallel
#haddock3 setup
conda create -n haddock3 python=3.9
conda activate haddock3
pip install haddock3
#install arctic3d (a software to find interaction region)
git clone git@github.com:haddocking/arctic3d.git
pip install arctic3d
arctic3d -h #not error => install successfull

** Note: 
- Currently, this repo can only work with X-Ray data not NMR data.
- arctic3d have an utility to input pdb file. However, in 12/11/2025, while i have tested in several protein with several times, this function is not work. Therefore, i suggested a new function which extract the uniprot ID of each chain in the header of each pdb file. This approach face with the concern about the precision of annote data. However, it reduce the runtime and not rely on external sever (blast sever) which may be the bottleneck when the sever is busy.
- Consider batch mode provided by haddock3 instead of writing "batch mode from scratch"
- Document have stated that can run with one multiple-chain protein but this approach face error when actually running => split chain is the default behavior.
- Note that this script might seem like a waste of resources because WSL maintains high memory usage even after the script completes the task. Don't worry; run the free -h command in the WSL terminal, and you will find that it isn't using as much memory as Windows Task Manager suggests.
